本階段不直接寫入 `trees`，而是先建立正式轉換規則。

## 二、目前樣本狀態

- 來源資料表：`nfi4_subrecords`
- 目標資料表：`trees`
- 目前 staging sample 筆數：20

## 五、目前判斷

目前不建議直接將 `nfi4_subrecords` 轉入 `trees`。

原因：

- 目前可確認 Height、Volumn、Crown 為候選欄位。
- 目前尚未確認 DBH / 胸徑欄位。
- 目前尚未確認 species_code / species_name 欄位。
- 目前尚未確認每一筆 nfi4_subrecords 是否等同一棵樣木。
- 因此現階段先建立轉換規則，不直接寫入 trees。

## 六、建議後續流程

1. 擴大 `nfi4_subrecords` 匯入樣本，不只匯入單一 plot_code。
2. 重新分析 raw_attributes 是否存在胸徑、樹種、樣木號碼等欄位。
3. 若確認存在樣木核心欄位，再建立 `nfi4_subrecords_to_trees_sample.py`。
4. 若 NFI4 子紀錄不等同樣木，則應另設正式明細表，而不是直接寫入 `trees`。
5. 最後再建立正式 `trees` ETL。
